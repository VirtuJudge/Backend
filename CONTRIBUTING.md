# Contributing

1. Pick an issue and read its linked files in the Docs repository.
2. Update the relevant contract or decision before changing shared behaviour.
3. Keep secrets in local environment files based on `.env.example`.
4. Add tests with the implementation.
5. Run the repository and application checks.
6. Review the full diff before pushing or opening a PR.

Use short branches and Conventional Commit subjects. A contract change needs review from both sides of the boundary.

See the [review workflow](https://github.com/VirtuJudge/Docs/blob/main/Planning/Review-Workflow.md).
